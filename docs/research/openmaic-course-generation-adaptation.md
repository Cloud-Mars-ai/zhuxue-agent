# OpenMAIC 课程生成机制与本项目适配

调研提交：`THU-MAIC/OpenMAIC@1b64116`

## OpenMAIC 的关键做法

OpenMAIC 的标准生成流程不是一次性让模型写完整课程，而是：

1. 上传资料先抽取为文本和图片；
2. 把用户原始 requirement、资料正文、学生背景和研究上下文一起送入
   `requirements-to-outlines` 提示词；
3. 模型先推断主题、目标受众、时长、语言和教学风格；
4. 只生成可审阅的 SceneOutline 数组；
5. 教师确认后，再按单个场景生成内容；
6. 每个阶段独立解析、校验、重试，失败时只重试失败阶段。

其提示词明确要求：

- 用户需求决定课程主题；
- 上传资料是内容依据，不能反过来覆盖用户需求；
- 信息不足时做合理默认，而不是改写成系统预设课程；
- 每个场景必须有明确的教学作用、要点和顺序；
- 输出严格 JSON，不能夹带说明或 Markdown。

## 原项目问题

原实现虽然已有两阶段结构，但存在三个偏差：

1. 主页把当前固定章节作为 `chapter` 传入，用户主题只是附加目标；
2. 材料检索把内置管理学纲要与用户资料放在同一候选池；
3. 模型失败后的本地兜底直接读取固定《管理学》章节。

因此无论用户输入什么，最终都可能得到管理学大纲。

## 已完成的适配

- 用户输入成为课程主题的第一依据；
- 上传材料被标记为高优先级、独立证据源；
- 新课程生成默认排除内置管理学材料；
- 资料不足时允许按用户主题组织通用课程，同时要求标注“待核对”；
- 大纲仍采用 OpenMAIC 的 requirement → outline → scene 两阶段结构；
- 模型不可用时，从用户主题和材料文本抽取要点生成确定性大纲；
- 单个场景的板书、练习和题目兜底也只读取当前场景要点，不再回到管理学章节。
