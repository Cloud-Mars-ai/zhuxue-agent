# 调研报告④：产品优化方向与策略（基于 OpenMAIC 对比与双视频逐帧分析）

> 日期：2026-11-08 ｜ 撰写：经管Agent项目组（深研研）
> 输入：报告①《OpenMAIC 产品调研报告》、报告②《OpenMAIC 生成课程视频逐帧分析》（172s/13 场景）、报告③《本项目生成课程视频逐帧分析》（86s/6 场景）
> 对比条件：**同一提示词**（有理数→实数，七年级数学），两条课程生成管线的产物同台竞技

---

## 1. 一句话结论

同一提示词下，OpenMAIC 的产物是**"完整体验的互动课堂"**（多智能体、可操作模拟、小测交互、完课数据页），本项目的产物是**"高可信度的结构化讲义"**（板书架构、可审计讲稿、苏格拉底卡、内容准确）——**体验层落后一个身位，信任层领先一个身位**。优化策略 = 体验层追平（完课闭环/小测交互/播放控制/可操作教具），信任层拉开（编译验证/题目质检/证据链），人格层轻量补课（提问条+可选 TTS），**绝不复刻多智能体聊天室**。

## 3. 优化方向与落地策略

### P0 · 演示前必须补（直接决定比赛观感）

#### P0-1 完课闭环（最高优先级）
- **问题**：报告③ D1——课程在讲稿列表处硬结束，观众得不到"学完了"的收束感与成就反馈。
- **对标**：报告② A1（s_161–s_172 完课页：奖杯 + 9页/2小测/2互动 + 29% + 点赞吐槽 + 场景导航）。
- **方案**：播放至最后一个 beat 后弹出**完课卡**：① 学习统计（板书板数 / 小测题数 / 互动次数 / 作答正确率）；② 「重新学习 / 返回课程 / 去练习」三个出口；③ 轻量反馈（有用/没用两按钮，写 localStorage）。数据全部来自本地 store，无需后端。
- **落点**：新增 `components/course/CourseCompleteCard.vue`；播放状态机接在 `CourseExperience.vue` 的 beats 播放入口；统计读 `stores/practice` + 本地 trace。
- **验收**：任意课程播放到底必出现完课卡；统计数据与实际作答一致。

#### P0-2 小测作答交互
- **问题**：报告③ D2——小测场景自动流过，学生无法作答，教学活动不闭环。
- **对标**：报告② A3（s_081–s_092：答题中 3/3、20s 倒计时、选项高亮、绿勾判定、计分）。
- **方案**：quiz 板增加作答态：选项可点（单选即时判定/多选提交后判定）、题号进度（第 x/y 题）、正确计数；判定后展开解析（现有 explanation 字段直接用）。倒计时可选（默认关，避免演示翻车）。
- **落点**：`utils/courseStudio.js` quiz 场景渲染分支 + `stores/practice` 记分；标识「演示缓存」规则不变。
- **验收**：小测板可完整作答并给出正确率；刷新后成绩保留。

#### P0-3 播放控制条 + 讲稿分拍步进
- **问题**：报告③ D4/D5——无暂停/倍速/跳转；结尾整屏 12+ 条 beats 4–8s 滚过，读不完。
- **对标**：报告② A7（s_026/s_084：场景导航、1x/2x 倍速、上下一段）。
- **方案**：① 底部播放条：播放/暂停、上一板/下一板、倍速（1x/1.5x/2x）、板内进度；② **讲稿面板默认折叠**，展开后按拍高亮当前 beat，与播放进度同步；③ 长 beats 列表改为「按拍步进」——每次只展开当前拍 + 前后各一拍。
- **落点**：`CourseExperience.vue` 播放控制 + 讲稿面板组件化（`components/course/BeatsPanel.vue`）。
- **验收**：观众可随时暂停提问；讲稿任意一拍可定位；全程无"文字墙硬滚"。

### P1 · 竞赛交付前应完成（形态追平）

#### P1-1 可操作教具（数轴/面积模拟器）
- **问题**：报告③ D7——数轴是静态图。
- **对标**：报告② A2（s_097–s_116：被开方数滑块 → 面积方块 + 数轴实时联动 + AI 解说同步）。
- **方案**：把大纲场景 03「数轴上的加法模拟」做成**可拖动组件**：数轴上两个可拖点 → 实时显示和/差/距离；复用现有 `scientificModel` 四字段契约（core_formulas/mechanism/constraints/forbidden_errors）驱动参数范围，失败降级为静态图（flags.offlineFallback）。
- **落点**：新增 `components/course/NumberLineLab.vue`；interactive 场景渲染分支接入；受控渲染铁律不变（参数化 SVG，无自由 HTML）。

#### P1-2 视觉素材受控升级
- **问题**：报告③ D6——纯文字框 + 手绘数轴，视觉单薄。
- **对标**：报告② A5（真实照片、函数图、坐标系填充图）。
- **方案**（全部走受控渲染）：① 参数化数轴/坐标系/函数曲线组件（ECharts 已在依赖内）；② 公式卡（KaTeX 或项目现有 md 渲染）；③ 图片生成能力纳入 flags 管控，**默认关**，开启时也必须过适配器白名单（形状/图表/照片槽位），加载失败显示占位骨架而非 ×（吸取报告② B2 教训）。
- **落点**：`theme/tokens.css` 增补图示语义变量；`components/course/figures/` 下按类型建组件。

#### P1-3 内容规模下限
- **问题**：同题 6 场景 vs 13 场景，内容覆盖薄。
- **方案**：大纲阶段设**场景结构下限**（导入 ≥1 / 讲解 ≥2 / 示例或模拟 ≥1 / 小测 ≥1 / 收束 ≥1，合计 ≥8）；compiler 已有 COVERAGE 类检查，将"结构完整性"纳入警告级约束；提示词侧在 requirements-to-outlines 模板中强化（OpenMAIC 提示词资产已内嵌，可对比其题型矩阵补强）。
- **落点**：`api/openmaic/outlineGenerator.js` 提示词 + `utils/courseValidator.js` 新增结构约束码（如 STRUCT-MIN-SCENES，warn 级）。

#### P1-4 题目质量校验（把 OpenMAIC 的坑变成我们的亮点）
- **问题**：报告② B1——小测选项重复（A=D、B=C），"哪一项"出现两个等价正确项；这是 AI 生成内容的典型缺陷。
- **方案**：courseValidator 新增两条校验码：
  - `QUIZ-DUP-OPTION`（选项文本去重，error 级——触发修复循环）
  - `QUIZ-SINGLE-ANSWER`（单选题 answer 唯一且与选项对应，error 级）
  - 顺带加 `QUIZ-OPTION-COUNT`（选项 ≥3，warn 级）。
- **落点**：`utils/courseValidator.js` + 对应修复策略进 `courseRepair.js`（确定性修复：去重/重编号；无法确定唯一解时摘该题并记 RepairRecord）。
- **验收**：构造重复选项用例，编译管线必须报错并修复；修复记录进自行检查报告。

### P2 · 有余力再做 / 赛后

#### P2-1 课堂人格化（轻量路线）
- **不做**：多智能体聊天室、圆桌辩论（与"结构化板书"铁律冲突，工作量巨大，且非赛题评分点）。
- **做**：beats 中的**设问拍**升级为对话气泡呈现（AI 助教头像 + 气泡 + 可选 TTS 朗读，`api/tts.js` 已存在），让"先测后讲"的提问有对象感。一屏一助手，不做多智能体。

#### P2-2 语音讲解（可选开关）
- 讲稿 beats → TTS 按拍朗读，默认关；开启时讲稿面板同步高亮当前拍。与 P0-3 的步进播放天然耦合。

#### P2-3 大纲审查体验微升级
- 抄 OpenMAIC 大纲卡的两个细节（报告② s_009–s_016）：场景**类型徽章**（讲授幻灯片/小测/交互/收束）+ **知识点芯片**（可删除 tag）。我方编辑器已有场景卡与来源标注，补这两项成本低、观感提升大。

## 4. 差异化策略主线（回答"我们凭什么不输"）

1. **体验层追平，不超越**：完课闭环、小测交互、播放控制、可操作数轴——这四项是"课堂像课堂"的底线，补齐即消除对比落差（P0+P1-1）。
2. **信任层拉开**：OpenMAIC 的视频实证了 AI 生成内容的典型事故（选项重复、占位符、语义不通评语）。本项目的**课程编译器六层管线（IR→验证→修复→证据账本→学科检查→实验）** 正是对症解药——P1-4 把"题目质检"做成可演示的校验码，比赛现场可以直接讲"我们的管线会拦住这类错误，并在修复记录里留痕"。**这是叙事级差异，比任何 UI 细节都值钱。**
3. **人格层轻量**：一个 AI 助教 + 提问气泡 + 可选 TTS，换取"课堂感"的 60%；多智能体聊天室的边际成本极高，明确不做。
4. **学情层独占**：赛题三项任务（内容梳理/学情分析/教学建议）要的是"结论能回到证据"。课程产物接入学情数据（40 学生/806 作答/54 题）后，完课卡的正确率、板的掌握度标注都能接真实数据——这是 OpenMAIC 没有也抄不动的层。

## 5. 实施顺序与工作量判断

| 批次 | 内容 | 依赖 | 判断 |
| --- | --- | --- | --- |
| 第一批（1–2 天） | P0-1 完课卡、P0-3 播放控制+讲稿折叠 | 无新增依赖，纯前端组件 | 投入小、观感回报最大，**最先做** |
| 第二批（2–3 天） | P0-2 小测交互、P1-4 题目校验码 | 动 courseStudio 渲染分支 + validator，需回归测试 | 与编译器主线合流，一次做齐 |
| 第三批（3–5 天） | P1-1 可操作数轴、P1-2 图示组件库、P1-3 规模下限 | scientificModel 契约复用；图示组件可增量加 | 形态追平的主力 |
| 第四批（余力） | P2-1 提问气泡、P2-2 TTS 朗读、P2-3 大纲徽章 | tts.js 已有 | 演示加分项 |

每批验收口径：P0 批 = E2E 主链路（生成→播放→完课卡→小测计分）全绿；P1 批 = 编译器质量门（`npm run test:course-compiler`）不降级 + 新增校验码有用例；P2 批 = 演示动线脚本走通。

## 6. 风险与明确不做

**风险**
1. 播放控制与 beats 播放状态机耦合深，改造需防回归——先补 E2E 再动刀（项目 E2E 基线此前丢失，正好借这批工作重建）。
2. 小测交互引入后，"AI 功能必须带本地确定性兜底"铁律仍适用：判定逻辑必须本地确定性实现，不得依赖模型。
3. 可操作教具的参数范围由 scientificModel.constraints 驱动，约束缺失时必须降级静态图并计数（adapter.dropped 同款机制）。

**明确不做**（与 AGENTS.md 既有清单一致，对比后更应坚守）
- 多智能体聊天室 / 圆桌辩论 / 同学智能体（复刻 OpenMAIC 人格层，成本畸高）
- 自由画布 PPT 与自由 HTML 场景（安全模型冲突，报告① §10 已论证）
- 语音克隆、课程集市、积分体系
- 为追规模而灌水场景（P1-3 的下限是结构完整，不是数量攀比）

## 7. 给比赛演示的三条直接建议

1. **演示脚本改用"对比叙事"**：同题双产物（本报告②③的帧证据）就是现成的台本——"同样一道题，OpenMAIC 的选项重复了，我们的编译器会拦下它"（P1-4 现场跑一遍修复记录，比任何功能列表都有说服力）。
2. **演示动线确保经过完课卡与小测作答**（P0 批落地后）：评审看到的最后一个画面应该是数据收束，不是文字墙。
3. **学情闭环至少接一个真实切面**：完课卡的正确率若能关联到课程知识点的班级掌握度（读取赛题数据的 806 条作答），"助学智能体"的定位才完整落地。
