# 赛题数据可用性梳理与处理方案

> 版本：v1 · 2026-11-07
> 范围：`【赛题材料】智慧学伴/赛题数据/赛题资料包` 全部资料
> 结论先行：**六张 CSV 学情数据已完整接入并可在产品中完整呈现；八本教材切片按"主题相关三本提取修复后摘录、其余五本保持索引"处理；课标 PDF 仅呈现页码索引；评测数据、赛方规则文档与 Excel 冗余副本不进入产品。**

---

## 1. 背景与目标

赛题资料包含学情数据、课程标准与教材切片、赛事规则文档三类资产。产品（智慧学伴工作台）只能使用其中一部分，需要回答三个问题：

1. 哪些数据能完整呈现，哪些只能部分呈现，哪些不呈现？
2. 每一类分别用什么机制落到产品和页面？
3. 版权、合规与数据边界如何声明？

本文件即上述问题的处理方案，并作为后续页面改造的依据。改造落地情况见第 7 节。

## 3. 三分类判定与处理机制

### 3.1 A 类：可完整呈现（六张 CSV 学情数据 + 42 条字段说明）

**判定依据**：结构化、体量小（合计约 120 KB）、无版权障碍、字段语义完整（字段说明.csv 自带数据字典）。

**处理机制**：

- 以 `?raw` 方式随前端构建打包（`src/competition/official/raw-sources.generated.js`），由 `officialDataset.js` 转换为数据契约对象；
- 统计、排序、推荐全部由确定性规则引擎计算（`analysis.js`），模型只做解释与课程表达；
- 质量问题（重复、修订、待评分、未作答、异常引用）单独报告，不静默删除；
- **本次新增**：42 条字段说明作为 `fieldDefinitions` 暴露到数据集，在工作台「内容与数据」步骤渲染为按表分组的数据字典，替换原先只在 `meta.counts` 里的一个数字。

### 3.2 B 类：部分呈现（教材切片 PDF + 课标 PDF）

**判定依据**：正文有教学价值，但体积大（八本切片约 34 MB、课标 38.3 MB），且存在技术障碍：

- 教材切片文本层 ToUnicode CMap 损坏——拉丁字母/数学符号被替换为形态相近的稀有汉字（狓→x、犿→m、狀→n、狆→p 等），直接提取会产生乱码；
- 课标 PDF 为图像扫描版，无文本层，提取需 OCR，识别质量与时间成本不可控。

**处理机制**：

| 资产 | 呈现方式 | 说明 |
| --- | --- | --- |
| 教材索引（B01—B08） | 章级索引卡片 | 册别、章节名、文件路径，来自 `题目与材料.csv`，全部 8 本保留 |
| 主题相关教材（B02/B05/B06） | **修复后正文摘录** | 与三个赛题主题直接对应的三本，经确定性乱码修复后提取限量段落，随构建打包为 `textbookExcerpts.js`（见第 4 节） |
| 其余教材（B01/B03/B04/B07/B08） | 仅索引 | 与本次三个主题无直接关联，控制公网包体积，不提取正文 |
| 课标 PDF | 页码索引 | `课程要求.csv` 自带"课标整理编号 + 文件页/印刷页"，逐条呈现，不做 OCR |
| 教材切片 PDF 原文件 | 不打包 | 约 34 MB，未复制进前端构建（交接文档第 424 行既有决策，维持不变） |

主题→教材映射沿用 `officialDataset.js` 的 `TOPIC_TEXTBOOK_IDS`：
T01 代数式与整式运算 → B05、B06；T02 方程与方程组 → B02、B06；T03 不等式与不等式组 → B02。

### 3.3 C 类：不呈现

| 资产 | 原因 | 处理 |
| --- | --- | --- |
| `模拟学情数据索引.xlsx` | 与六张 CSV 同构（参赛说明原文"Excel 与 CSV 结构一致"），双源并存会产生不一致风险 | 不接入；数据字典取 CSV 版 `字段说明.csv` |
| 独立评测数据 | 评审时才提供，当前不存在 | 不呈现；产品在数据边界卡中显式声明 |
| 赛方补充记录 | 未提供 | 不呈现 |
| 真实学生信息 | 赛题明令禁止 | 不呈现；产品只用脱敏模拟学生（D01—D40） |
| 赛事规则/说明文档（pdf/docx ×4） | 赛事组织材料，非学情数据；其约束已落入数据契约、任务条件与典型案例核验模块 | 不呈现；关键约束摘入数据边界卡 |

## 4. 教材摘录提取方案（B02 / B05 / B06）

### 4.1 目标

把三本主题相关教材的正文以**修复乱码后的纯文本摘录**形式接入产品，支撑：

- 工作台「内容图谱」中教材 chip 可展开正文，教师核对"要求—教材—题目"出处链；
- 课程生成时把教材摘录作为材料来源引用（`chapter`/`sources` 已有结构，无需改 schema）；
- 让学生端"内容图谱"同样可读教材原文。

### 4.2 提取管线（离线脚本，构建前执行一次）

```
B0x_相关资料切片.pdf
  → pdfjs-dist 6.5.438 getTextContent（Node）
  → textRepair.repairText 确定性修复（狓→x 等 38 字母 + 槡→√ + 图示部件删除）
  → 按章节标题切分（"第X章 / X.Y 小节"正则）
  → 每节限量保留段落（默认 ≤ 6 段、每段 ≤ 240 字，去页眉页脚与目录行）
  → 生成 frontend/src/competition/textbookExcerpts.js（随构建打包）
```

### 4.3 质量与体积预算

- **质量闸门**：生成后逐本输出修复统计（修复字符数、删除图示部件数、可疑区块清除数）；摘录文本再过一次 `detectGarbled` 抽检，残留可疑字必须为零；
- **体积预算**：摘录文件 ≤ 60 KB（gzip 前），三本合计摘录段落 ≤ 90 段——只做"出处核对"用途，不做全文检索，避免把 34 MB PDF 的问题搬进公网包；
- **可复现**：脚本固定在 `frontend/scripts/extract-textbook-excerpts.mjs`，赛方若更新切片可一键重生成；
- **降级路径**：PDF 缺失或提取失败时，脚本报错退出而不是写入半个文件；产品侧 `textbookExcerpts` 为空数组时教材 chip 自动回退为纯索引展示，不影响其他功能。

### 4.4 版权与合规

- 资料说明.txt 原文："相关资料切片不涉及版权问题，仅供个人学习使用"——摘录仅用于本次比赛作品演示，产品内在数据边界卡中保留该声明；
- 摘录附带教材编号、章节与文件路径，保持可回指；
- 乱码修复过程在方案与日志中留痕（修复规则见 `src/utils/textRepair.js` 头注释），不静默改写原文语义。

## 5. 数据边界与合规声明（产品内呈现）

工作台「内容与数据」步骤新增**数据边界卡**，固定声明五条：

1. 学生、班级、分数与作答过程均为**模拟数据**，仅限本次比赛开发、分析与展示，禁止引入真实学生个人信息；
2. 教材切片"不涉及版权问题，仅供个人学习使用"（资料说明原文）；
3. 教材正文为**修复文本层乱码后的摘录**，可能与纸质教材存在排版差异，核对请以原书为准；
4. 课标仅呈现整理编号与页码索引，未做 OCR 全文；
5. **独立评测数据**由赛方在评审时另行提供，当前产品不包含、不预测。

## 8. 后续可选（本次不做）

- 若评审需要全文检索：对 B01—B08 全量提取修复后建前端索引（预计 +200 KB），或改服务端检索；
